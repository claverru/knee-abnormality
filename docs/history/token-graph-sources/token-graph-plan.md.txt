# Token graph plan

Planned on 2026-09-14. Implements the geometric interaction layer from the
[position research](docs/research/position-encoding.md#5-recommended-sequence): a
k-nearest-neighbour graph neural network over spatial tokens, placed before target
attention. Implemented on 2026-09-14 and retired on 2026-09-15 because two trained runs
did not use the graph; see the [result](docs/validation/2026-09-14-token-graph-result.md)
and the [modeling summary](docs/modeling/active-spatial-token-model.md#retired-token-graph).
The champion baseline diagnostic was skipped (section 5). The runs' source archives,
`outputs/token-graph/source_snapshot.zip` and `outputs/graph-forced/source_snapshot.zip`,
recover the implementation.

## Objective and comparison

Test whether letting tokens exchange information with their in-plane, same-series
and cross-plane neighbours improves study-level predictions. In particular, test
whether sagittal tokens can borrow compartment context (fibula, MCL, plateau shape)
from coronal and axial tokens at the same patient location. This is a deliberate
high-risk experiment. The measured headroom for medial/lateral discrimination alone
is small (about +0.004 macro), so a win must come from better use of anatomy context
across several targets.

Compare with the champion `reflection-sigma40`: **0.892360168 fold-0 macro AUC, 0.936 public**.
Keep its recipe fixed:
- ReXNet-200, Steven v4 with gold overrides, seed 42, `all_5fold_v3` fold 0;
- 224 px / 140 mm triplets, sigma 40, reflection 0.5, series dropout 0.2;
- independent attention heads and classifiers, observed-target BCE;
- optimizer, batch 8, 16 workers, ten epochs, 2× validation density.

Use a fresh `token-graph` run. Preserve CoAtNet support.

The run changes two things together: it adds the graph and removes the unused additive
3D embedding, whose role the graph takes over. One run cannot separate them. The
knee-side checkpoint's removal diagnostic showed the 3D embedding contributing nothing
(+0.00004 macro when removed).

## Decisions confirmed before implementation

The user confirmed these recommended choices on 2026-09-14.

1. **Replace the additive 3D embedding.** 3D geometry enters only as relative edge
   geometry. Remove the 3D MLP, `unknown_3d`, study-level 3D dropout and the
   model's use of the study center.
2. **Raw tokens as nodes,** with no voxel pooling: every backbone location of every
   sampled triplet, about 1,600 per training study and 3,100 per validation study.
3. **Local kNN graph, not a transformer.** Two message-passing layers with neighbours
   fixed by geometry. A global layer or virtual node is a later hybrid, not part of this run.
4. **Pure PyTorch.** No `torch_geometric` or `torch_scatter`, so the Kaggle bundle and
   notebook need no new dependency.

## 1. Graph construction

Build the graph in `encode_batch` after `feature_geometry`, in float32 outside autocast,
without gradients. Nodes are the flattened `[images × H × W]` tokens. Edges never
cross studies.

### Node attributes

- **Patient point:** the middle-slice LPS anchor in mm from `feature_geometry`, with
  the existing reflection matrix `S = diag(−1, 1, 1)` applied to the absolute point
  rather than the centered one.
  - Relative offsets are identical either way, so the study center is no longer needed.
  - Reflection mirrors pixels and offsets together, so a reflected study stays a
    plausible opposite knee.
- **Geometry validity:** `geometry_valid` and finite points, independent of
  `center_valid`. Tokens from series with unreliable native geometry keep grid edges only.
- **Membership:** study, prepared series (`acquisition_index`), plane
  (`plane_lookup[token_type]`) and visual validity.
  - Visually invalid tokens neither send nor receive messages; they are already
    excluded from pooling.

### Edges

Each node has K = 20 incoming slots, padded with a mask:

| Type | Slots | Definition |
|---|---:|---|
| Grid | 8 | The 8-neighbourhood on the same image's H × W feature grid; needs no patient geometry |
| Same series | 4 | Nearest geometry-valid tokens from other sampled triplets of the same series, within 30 mm |
| Other series | 8 | Nearest geometry-valid tokens from other series of the study, within 30 mm; typed as same plane (other contrast) or cross-plane |

- **Nearest-neighbour search:** per study, `torch.cdist` over geometry-valid,
  visually valid tokens, with disallowed pairs set to infinity before `topk`.
  - About 3,100² distances per validation study (roughly 40 MB); loop over the batch's studies.
- **Radius:** 30 mm is about one token-cell diagonal (20 mm grid) plus a triplet slab.
  Neighbours beyond it are masked, so series that do not overlap exchange nothing.
- **Why other-series slots are separate:** without them, same-image and same-series
  tokens would fill all 16 nearest places and sagittal tokens would get no cross-plane messages.

### Edge features

An 11-value vector per edge:
- patient offset Δxyz / 50 mm and distance / 50 mm, zero when either endpoint lacks geometry;
- a flag for whether both endpoints are geometry-valid;
- a one-hot edge type: grid, same series, other series same plane, cross-plane;
- grid row/column offsets in {−1, 0, 1}, zero for non-grid edges.

### Geometry dropout

During training, drop every same-series and other-series edge for 10% of studies,
keeping grid edges.
- One draw per study per forward, from the seeded Torch RNG.
- It replaces the retired 3D dropout and teaches the model to work when cross-series
  geometry is missing or misregistered.
- Evaluation keeps all edges.

## 2. Message-passing block

Node state starts from the existing pre-norm sum, without the 3D term:

```text
h_i = appearance_i + position_1d_i + position_2d_i + plane_i + contrast_i
```

Each of the two layers applies a residual GATv2/EdgeConv-style update:

```text
x_i   = LayerNorm(h_i)
q_i   = W_q x_i                     256 → 128
k_j   = W_k x_j                     256 → 128
u_ij  = GELU(W_1 [q_i, k_j − q_i, E e_ij])   (128 + 128 + 32) → 128;  E: 11 → 32
a_ij  = softmax over valid slots j of (w_a · u_ij)     computed in float32
h_i  ← h_i + W_o Σ_j a_ij u_ij      128 → 256, zero-initialized
```

Then apply the existing `mil_norm`, target attention and linear classifiers unchanged.

- **Non-equivariant on purpose:** the message sees the signed Δxyz, so medial and
  lateral relations remain distinguishable. Relative anatomy defines them; metadata
  knee side is not used.
- **Starting point:** `W_o` starts at zero, so the initial graph block is an identity
  and initial predictions match a champion without the 3D embedding.
  - Initialization is not bitwise identical to the champion, because removing the 3D
    modules changes the random draws for the plane and contrast embeddings.
- **Isolated nodes:** a node with no valid slot receives no update.
- **Size:** about 140k parameters per layer, 280k total, following the head learning
  rate and existing weight-decay rules.
- **Memory estimate:** a training batch has at most about 12,500 tokens × 20 slots. At
  bf16, stored per-edge activations are roughly 400 MB per layer, on top of the
  champion's 20.5 GB peak on a 24 GB GPU.
  - Measure before the full run (section 6). If the peak exceeds about 23 GB, apply
    activation checkpointing to the graph block as fixed behaviour.
  - Kaggle inference runs FP32 on 16 GB T4s with four studies per GPU. Graph tensors
    there are transient, roughly 600 MB per layer, and must be checked in export verification.

## 3. Removal of the additive 3D embedding

- **`spatial_tokens.py`:** remove `position_3d`, `unknown_3d`, 3D dropout and the
  centered `xyz` output. `feature_geometry` returns reflected absolute points and
  geometry validity instead of `available_3d`.
- **`model.py`:** stop reading `study_centers`/`center_valid`, and drop the
  `position_3d` term from `pool_encoded`.
- **`dataset.py`:** remove `study_centers`/`center_valid` from `collate_studies`.
  Study references stay inside the dataset for physical sampling; reflection
  eligibility is unchanged.
- **`scripts/tools/preview_augmentations.py`:** compute its displayed centered anchors
  from the returned absolute points and its own study reference, and show geometry
  validity instead of 3D availability.
- **`augmentation.py`:** update the `REFLECTION_IDENTITY` strings that mention
  `unknown_3d` and 3D dropout.
- **Retire superseded work:** the future-work entry to delete the 3D encoding is
  absorbed here; move it to ongoing work when implementation starts.

## 4. Integration

- **`encode_batch`:** returns node points, geometry validity, image/series/plane
  membership, the graph (neighbour indices `[nodes, K]`, slot mask, edge types,
  edge features) and the training geometry-dropout decision.
- **`pool_encoded`:** runs the graph blocks before `mil_norm`. Diagnostics can then
  recompute graph variants from one backbone pass.
- **Where the code lives:** a new `src/knee_abnormality/token_graph.py` with graph
  construction and `TokenGraph`. `preprocessing_identity.py` already hashes `model.py`
  and `spatial_tokens.py`; add `token_graph.py` to its explicit path list.
- **Configuration:** add `model.graph_layers: 2` and `model.graph_geometry_dropout: 0.10`,
  the intended experiment parameters. The 20 slots, 30-mm radius, message width 128 and
  edge feature layout are fixed and versioned.
- **Identities:**
  - `SPATIAL_TOKEN_IDENTITY`: new algorithm name, 3D entries removed, a `token_graph`
    block describing nodes, edges, features, block, initialization and dropout.
  - Bump the preprocessing identity algorithm name.
  - Old checkpoints are rejected by the existing strict identity and state-dict checks.
- **Callers to review:** training, inference, export and its quick verification,
  profiling (`profiling.py`, `scripts/adhoc/profile_training.py`,
  `scripts/adhoc/profile_threaded_loading.py`), the preview tool and the encoding diagnostic.
- **Documentation:** active spatial-token model, model-shape diagram, spatial-token
  geometry, the position research doc and the script catalog, all updated in the
  implementation change.

## 5. Diagnostics

### Before implementation: champion baseline (skipped)

`scripts/adhoc/diagnose_encoding_usage.py` was extended as planned:

- **Plane-only variants** (sagittal, coronal, axial): mask the visual validity of other
  planes' tokens. Report metrics on studies that have that plane, with study counts;
  the others are skipped for that variant.
- **Compartment metrics for every variant:**
  - meniscus and OA exclusive-positive margin AUC;
  - lateral cross-talk: the share of lateral false positives, at the prevalence
    threshold, that are medial-positive.

**The GPU run on the champion checkpoint was skipped by user decision on 2026-09-14.**
The graph implementation then changed the diagnostic to the new model, so the pre-graph
plane-only variants were never measured. Consequence: plane-only margins will exist only
for the graph checkpoint, and a sagittal-only gain cannot be compared with the champion.
The champion's full-fold references come from its saved predictions through
`scripts/tools/compare_fold_runs.py`: macro AUC 0.892360, margins 0.9690 (meniscus) and
0.8791 (OA), and lateral cross-talk 68.9% and 63.9%.

### After training: graph interventions

Recompute from one backbone pass:
- without the graph;
- without grid, same-series, other-series or cross-plane edges;
- the plane-only variants;
- the existing 1D, 2D, plane and contrast removals. Remove the 3D variants.

A cost for removing cross-plane edges is the mechanistic evidence that cross-plane
context is used. Without the skipped champion baseline, sagittal-only margins can be
read only against the graph checkpoint's own intact and full-fold values.

## 6. Verification and evaluation

**Before handing back for training:**
- Ruff, formatting, catalog consistency and link checks.
- Static review of: neighbour construction never crossing studies or using invalid
  tokens; masked softmax with isolated nodes; zero initialization; reflection sign
  handling; dtype boundaries; optimizer inclusion; CoAtNet grid shapes.
- No tests. GPU work only when requested.

**Memory check** (user-launched on a free GPU, before the full run):

```bash
rtk proxy uv run --locked python -m scripts.adhoc.profile_training configs/baseline.yaml --output-dir outputs/profiling/token-graph-gpu --mode gpu --batch-sizes 8 --samples 8 --warmup 1 --steps 2
```

The capacity profiler was extended for this command: it accepts batch sizes up to eight,
samples the eight maximum-load training studies, and disables series and graph geometry
dropout.

**Training:** `rtk proxy uv run --locked just train token-graph`.

**Comparison:** generalize `scripts/adhoc/analyze_knee_side_embedding.py` into a
reusable fold-run comparison tool in `scripts/tools/`. The allowed configuration and
identity differences are CLI inputs. It reports, from saved predictions and checkpoint
tensors on CPU:
- full-fold and per-target AUC, BCE, gold and report-derived metrics;
- medial/lateral pair, OA and other-eight families with report-group bootstrap intervals;
- exclusive-positive margins and lateral cross-talk;
- vendor strata with supports;
- epoch curves, timing and peak memory.

**Reading the result:**
- **Graph unused:** removing the graph changes predictions negligibly. Retire the graph,
  whatever the macro AUC.
- **Graph used, macro within noise (about ±0.003):** the decision rests on mechanistic
  gains (sagittal-only margin, cross-talk, localized targets such as Baker's, fracture
  and contusion). Candidate follow-ups: a public submission, a second seed, or the
  global-context hybrid.
- **Clear macro gain:** export, check the Kaggle inference memory and runtime, submit,
  then decide promotion.

## Risks

- **Weak labels plus extra capacity** may fit acquisition shortcuts; watch vendor strata
  and public score.
- **Misregistration between series:** different frames of reference or patient motion
  put wrong neighbours on cross-plane edges. Mitigated by the radius, attention
  weighting and geometry dropout.
- **Sparse sagittal sampling:** sampled slabs can be far apart, leaving few same-series
  neighbours within 30 mm. Record edge counts per type in the diagnostic.
- **Memory headroom** on the 24 GB training GPU and the 16 GB T4 inference GPUs.
- **Confounding with 3D removal:** a regression would not show which change caused it.
  The 3D term's measured contribution was about zero.
