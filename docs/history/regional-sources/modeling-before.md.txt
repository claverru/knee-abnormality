# Historical regional modeling notes

Snapshot before replacement; references are relative to the original docs/modeling.md.

### Active spatial fusion model

The active implementation uses **27 spatial queries, separate axial/coronal/
sagittal attention with shared projections, one attention head of width 64,
and ordinary eager PyTorch execution**. The
[spatial token plan](../spatial-token-plan.md) will replace this branch with direct
MIL over spatial tokens and five embeddings; that change is not implemented
yet. The
[earlier runtime rejection](validation.md#2026-09-12-spatial-fusion-engineering-result)
describes historical variants. The trained `spatial-fusion-radius` checkpoint
selected epoch 8 at 0.88635162 validation AUC, close to `crop140mm`. Its
[usage diagnosis](validation.md#2026-09-13-per-plane-fusion-usage-diagnosis)
finds that regional tokens receive 4.94% of final attention on average and
provide a small measured contribution on this fold.

One shared ReXNet pass produces the final 7×7 feature grid. The global branch
reduces its 49 positions independently for each of the 2,560 feature channels,
using `model.global_pool: avg` or `model.global_pool: max`, then projects to 256
dimensions. Global triplet descriptors retain their type and one-dimensional
position encoding. A separate 64-dimensional projection supplies all valid
local observations to cross-attention, with keys and values projected and packed
once. Three attention calls reuse that bank with separate plane masks, without
copying the bank per plane. Queries lie on the Cartesian
`{-35, 0, 35}` mm grid around the accepted study center. The finite distance
preference uses a 35-mm scale, and the learned geometry MLP includes orientation
and triplet depth. The shared residual MLP operates on each plane vector in
`[B, 27, 3, 64]`; missing or uncovered groups are zeroed after the residual.
Empty attention groups receive a temporary valid anchor to keep softmax finite,
and their outputs are then discarded. Concatenating axial, coronal and sagittal
vectors gives `[B, 27, 192]`, followed by a linear projection to 256 dimensions.
The existing query-position and source embeddings and final MIL are retained.

A query/plane group is covered when at least one valid anchor is within the
fixed **18-mm radius** selected [below](#per-plane-coverage-radius). Coverage is
an eligibility rule; a covered group attends to all valid tokens of its plane
using the unchanged 35-mm distance preference. Coverage is recomputed from
the selected, augmented anchors on every forward pass. A regional query needs
an accepted study center and coverage from at least two planes. Its `[B, 27]`
validity reaches final MIL, and invalid regional tokens are zeroed after their
embeddings and normalization. Global tokens remain available even when no
regional query qualifies.

The current YAML selects `model.global_pool: avg`. This setting changes only the
global branch's reduction; spatial attention still receives all 49 positions,
and final MIL still uses learned attention. Both choices produce a 2,560-feature
vector per triplet. Pooling is recorded in the effective configuration and
checkpoint, and prediction/resume validation rejects a pooling mismatch.
The completed `spatial-fusion` reference used average pooling. The
[max-pooling comparison](validation.md#2026-09-13-max-pooling-validation-comparison)
selected epoch 10 at 0.87907846 validation AUC, below the average-pooling
reference's 0.88416888. This does not support promoting max pooling.

Strict determinism is disabled with `trainer.deterministic: false`, while
seed 42 and worker seeding remain enabled. The initial max-pooling attempt
failed because PyTorch's CUDA adaptive max-pooling backward does not support
strict deterministic execution. The current setting permits that operation;
it does not replace the pooling implementation. Repeated training runs can
differ despite the fixed seed; see
[PyTorch's reproducibility guidance](https://docs.pytorch.org/docs/2.10/notes/randomness.html).
The completed average-pooling reference used strict determinism, so record
this execution-setting difference when comparing results.

The active path retains fixed triplet packing, vectorized preparation geometry,
factored geometry projection and direct valid-image indexing. Query count,
attention width, plane order, coverage radius and eligibility are fixed algorithm
semantics recorded in `preprocessing_identity`, under fusion algorithm
`per_plane_spatial_queries_v1`. Earlier joint-attention checkpoints require their
archived sources, as do the reduced compiled variant and global-only controls.
Current checkpoints also fingerprint model and augmentation sources.

From the repository root, train with:

```bash
rtk proxy uv run just train spatial-fusion-per-plane
```

`spatial-fusion-per-plane` is the run ID. The existing recipe uses `configs/baseline.yaml`,
which now selects the active fusion implementation with fold 0, seed 42, ten
epochs, batch eight and the frozen midpoint input allocation. Artifacts go to
`outputs/spatial-fusion-per-plane/`; choose another run ID if that directory already
exists. Changing the configuration does not launch training. Use a fresh run
for the per-plane architecture, with the same pretrained backbone initialization policy
as the average-pooling reference.

A bounded real-data Lightning run of the earlier average-pooling implementation
completed two optimizer steps at batch eight
with BF16 mixed precision and finite measured loss (0.674147). Peak allocated
GPU memory was 16.26 GiB on the RTX 3090. Its configuration, source snapshot,
label/split provenance and results are saved under
[`spatial-fusion-restored-eager-check-20260912`](../outputs/analysis/spatial-fusion-restored-eager-check-20260912/results.json).
This verifies that earlier training path; it does not validate the current
per-plane implementation or establish a matched runtime or accuracy result.
No tests were written or run.
