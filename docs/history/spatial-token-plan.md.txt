# Spatial token implementation plan

Status: agreed direction, pending implementation. Treat the complete change as
one experiment. This document describes future behavior; the current regional
implementation remains documented in [modeling](docs/modeling.md#active-spatial-fusion-model).

Replace global average pooling and the regional-query branch with direct
target-specific attention pooling over every valid spatial feature token.
Add five embeddings: 1D position, 2D position, 3D position, plane and contrast.

**The user will launch training after implementation. Do not start or schedule
training, including short training checks, optimizer steps, baseline reruns or
automatic comparison jobs.** Implementation ends with code, documentation,
static checks and a manual training command. The later encoding diagnostic is
also a separate, manually invoked command.

## Motivation and experimental scope

The [per-plane usage diagnosis](docs/validation.md#2026-09-13-per-plane-fusion-usage-diagnosis)
found 4.94% mean regional attention. Omitting regional tokens reduced AUC by
0.00069668 within that checkpoint; the independently trained fusion model
exceeded `crop140mm` by only 0.00022998 AUC on 904 validation studies. These
single-fold results do not establish a repeatable fusion advantage.

The new hypothesis is that final MIL can select useful spatial evidence
directly, preserving the backbone grid without the regional-query bottleneck.
This is position-aware selection and aggregation; it does not register images
or explicitly match tokens between views. The effect of the five embeddings
and removal of the regional branch will be evaluated together, without a
required sequence of intermediate architectures or separately trained ablations.

Use ReXNet-200 and the existing 224-pixel, 140-mm triplet recipe first. Keep
the sampling, labels, loss, optimizer, image augmentation and training budget
fixed. The old roadmap's learned bandwidth, finer fusion features and adaptive
regional queries are retired from the active plan. Do not retain those branches
or add switches for pooled tokens, reduced grids or regional fusion.

## Token representation

Let `N` be the number of retained triplets and let the backbone return
`[N, C, H, W]`. Flatten only the spatial dimensions and apply the same learned
`Linear(C, 256)` to every feature vector:

```text
[N, C, H, W]
    → [N, H × W, C]
    → [N, H × W, 256]
    → add five embeddings
    → LayerNorm(256)
    → target-specific attention MIL over valid tokens in each study
    → 12 study logits
```

ReXNet currently gives `C=2560`, `H=W=7`: 49 tokens per triplet, up to
3,136 before spatial validity masking at the existing 64-triplet validation
budget. Preserve all valid locations. Do not insert local average pooling,
token selection, a global summary token or full token-to-token self-attention.
Retain the existing 256-to-128-to-12 attention scorer and per-target heads.
Its score count is proportional to the number of tokens, not its square.

Every additive term has width 256:

| Term | Input and implementation | Shared across |
|---|---|---|
| Image features | Shared learned projection from the backbone's `C` channels | Projection weights shared across all locations and views |
| 1D position | Existing sinusoidal encoding of the middle slice's physical distance from its acquisition midpoint | All spatial tokens in a triplet |
| 2D position | Normalized horizontal/vertical input-image anchor; `Linear(2, 64) → GELU → Linear(64, 256)` | Encoder shared across all tokens |
| 3D position | Centered, scaled Cartesian XYZ; `Linear(3, 64) → GELU → Linear(64, 256)` | Encoder shared across all tokens |
| Plane | Learned three-entry embedding: Axial, Coronal, Sagittal | Tokens with the same plane |
| Contrast | Learned two-entry embedding for the existing metadata pairs `(fluid_sensitive, fat_suppression) = (0, 0)` and `(1, 1)` | Tokens with the same contrast category across planes |

Replace the existing six-entry joint plane/contrast embedding. Construct plane
and contrast lookup buffers from the configured series-type metadata, rather
than assuming a slot ordering. Keep the two contrast categories' existing
meaning; do not relabel them as T1/T2 or add unsupported combinations.

Keep 1D and 2D embeddings present throughout training and inference. In
particular, 2D identifies different locations within a triplet when shared
3D geometry is unavailable. Use coordinate encoders rather than fixed tables
with one entry per feature-grid location. Do not add learned gates, polar
coordinates, Fourier alternatives or separate dropout settings for each term.

## Backbone geometry and coordinates

Tokenization and MIL must accept variable `H` and `W`, including rectangular
grids. Set projection input width from the selected backbone's actual `C` when
constructing the model. A different backbone gets its own projection and fresh
training; changing grid dimensions does not require a new position table.

Give each supported backbone a verified feature-to-input mapping. For a regular
grid, this specifies row/column stride and the first anchor's pixel offset:

```text
input_x = origin_x + column × stride_x
input_y = origin_y + row × stride_y
```

Implement the verified ReXNet mapping first: stride 32 and origin 0 in both
axes. Keep architecture-specific derivation/validation at the backbone boundary;
the shared token geometry must not hardcode 7, 49 or 32. Grid dimensions alone
are insufficient to infer anchor positions. Fail clearly for a backbone whose
spatial layout or mapping is unsupported; do not silently distribute anchors
uniformly across its image. Additional backbone adapters are future work.

For 2D, normalize the actual anchor coordinates in the augmented input image:
`u = 2 × input_x / (input_width - 1) - 1` and likewise for `v`. This requires
no patient geometry, works across grid sizes and retains the model's image-frame
reference under augmentation.

For 3D, map each anchor through the actual inverse augmentation affine and the
prepared-pixel-to-patient transform of the triplet's middle slice. Reuse the
existing DICOM geometry and accepted shared study-center calculation, keeping
its reliability thresholds and its independence from sampled image counts and
series dropout. Do not change image selection or recenter the pixel crops.

```text
position_xyz = (anchor_in_patient_LPS_mm - accepted_study_center_mm) / 100.0
```

Use the same fixed 100-mm scale for every axis and study. Preserve physical
distance; do not normalize vectors to unit length, normalize each study by its
extent or clip valid coordinates to a unit cube. The middle-slice point is a
representative anchor for a feature whose receptive field overlaps neighboring
locations and mixes all three input slices, not an isolated voxel measurement.
Calculate geometry in float32 outside mixed-precision autocast, and cast the
resulting embeddings to the visual-feature dtype when assembling tokens.

## Validity and missing geometry

Separate two masks that are currently combined in the regional feature path:

- **Visual validity:** the triplet is retained and the anchor, after inverse
  augmentation, lies within the prepared valid image rectangles in all three
  channels. This controls participation in MIL, independently of DICOM pose.
- **3D availability:** visual validity plus valid native poses for the triplet,
  accepted series geometry (`SeriesGeometry.reason is None`), an accepted
  study center and finite mapped coordinates. This controls the 3D embedding
  only. Regional radius and two-plane-per-query coverage do not apply.

Propagate the series-level reliability decision from indexing through
preparation and collation. The current `native_poses_valid` flag alone is
insufficient: it can remain true for a series rejected for inconsistent
orientation, center line or frame IDs. Such a series must receive `unknown_3d`
even when other series establish an accepted study center. Its visually valid
tokens and their other embeddings remain available. Preserve the existing
policy that different frame IDs across series are recorded rather than rejected;
the inconsistent-frame rejection concerns IDs within one series. Do not use
`CenterProjection.reason` as this mask: an out-of-range projection of the study
center does not invalidate an otherwise reliable series' native coordinates.

Retain visually valid tokens whose 3D position is unavailable. Use one learned
256-dimensional `unknown_3d` vector in place of their 3D encoding. Do not pass
fake zero XYZ through the encoder as if the token were at the knee center, or
allow invalid/NaN coordinates to reach the encoder. Retain 1D, 2D, plane and
contrast information on these tokens.

Preserve existing image preparation handling when no usable triplet exists,
and report a clear failure if a study has no visually valid spatial tokens;
never apply softmax to an entirely masked study. An unavailable study center
alone must not cause such a failure.

The current 1D recipe requires a physical position from DICOM geometry or
`SliceLocation`; it is not metadata-free. Preserve that input contract and its
existing rejection behavior when 1D information is also unavailable. Do not
introduce a slice-index fallback in this change.

## Training-time dropout

Fix 3D whole-encoding dropout at probability **0.10 per eligible study per
training forward**. Eligibility means at least one retained token has usable
3D coordinates. Use one sampled decision for all tokens in that study: replace
their available 3D embeddings with the same learned `unknown_3d` vector used
for naturally missing geometry. Do not drop the images, alter their visual
validity or rescale surviving embeddings as ordinary elementwise dropout does.

Use the existing seeded PyTorch training RNG. Record the rate and study-level
masking semantics in the model identity. Keep 1D, 2D, plane and contrast
embeddings present, the existing series dropout at 0.20, and the current
attention scorer dropout setting. During evaluation, disable artificial 3D
dropout and use every reliable position. The 0.10 rate is an initial
experimental choice, not a measured optimum.

## Implementation sequence

1. **Backbone and token geometry:** introduce a focused spatial-token module
   under `src/knee_abnormality/` for the verified anchor mapping, independent
   validity masks and coordinate encoders. Adapt `model.py` to expose spatial
   features and infer `C`, `H` and `W` without calling the global pooling head.
2. **Embeddings and pooling:** implement the five additive embeddings, shared
   unknown vector and study-level 3D dropout. Flatten spatial tokens with the
   correct study, series-type and triplet membership; retain existing MIL
   scoring, normalization and heads. Avoid rerunning the backbone per target
   or copying feature banks per plane.
3. **Remove superseded production code:** delete `SpatialPooling`, regional
   queries, coverage and distance-bias machinery, and regional token packing.
   Move reusable geometry out of `spatial_pooling.py` before deleting it.
   Remove now-unused `input_slots`, `max_study_inputs`, depth/orientation
   payloads and related callers after checking their consumers. Keep patient
   maps, valid rectangles and reliability information required by local tokens.
4. **Configuration and checkpoint identity:** replace the obsolete pooling
   configuration with the single spatial-token path and give the baseline a
   descriptive fresh run name. Update source fingerprints, algorithm identity,
   backbone mapping, encoding definitions, metadata lookup order and dropout
   semantics. Update resume/prediction/export consumers. Reject historical
   checkpoints under current sources; retain their original bundles rather
   than aliases, state-dict migration or architecture-selection flags.
5. **Manual diagnostic:** implement the post-training procedure below as a
   separate command, without attaching it to training callbacks or recipes.
   Consult the script index/maintenance skill and update the owning catalogs.
   Retire regional-only coverage/profiling/usage scripts from the active
   workflow, preserving their sources and recorded results for historical
   reproduction. Do not leave broken imports of deleted production modules.
6. **Documentation and handoff:** update modeling, geometry/preparation,
   architecture, inference and script guidance affected by the implementation.
   Update `schema.md` to the implemented flow, keeping it exclusively a fenced
   Mermaid diagram. Preserve earlier fusion findings with historical labels.
   Provide the user with the fresh run's manual training command.

Implement fixed decisions directly. The diagnostic may intervene on an
embedding locally; it must not introduce selectable production architectures or
training flags for removing individual embeddings.

## Manual post-training encoding diagnosis

Prepare a CLI such as `scripts/adhoc/diagnose_encoding_usage.py`, using
`pydantic-settings` and Polars. It accepts a user-selected trained run/checkpoint
and a fresh output directory. Do not execute it automatically when training
finishes, and do not train or modify checkpoint weights in the command.

Validate saved configuration and source identities, run in evaluation mode,
and use the same full held-out fold and deterministic selected images for every
variant. Compute projected backbone features once per batch and reuse them
for all interventions. Recompute the embedding sum, LayerNorm and MIL each
time, preserving token membership and visual validity.

| Variant | Intervention before LayerNorm |
|---|---|
| Intact | Keep every normally available embedding |
| Without 1D | Omit the complete 1D embedding |
| Without 2D | Omit the complete 2D embedding |
| Without 3D | Replace available 3D embeddings with `unknown_3d` |
| Without plane | Omit the complete plane embedding |
| Without contrast | Omit the complete contrast embedding |
| Without position information | Omit 1D and 2D; replace 3D with `unknown_3d` |

Record intact prediction agreement with the run's saved validation predictions,
macro and per-target AUC, soft-target BCE, and absolute probability changes.
Report geometry availability counts and the 3D intervention on both the whole
fold and the subset receiving valid 3D information. Do not report AUC for a
target/subset lacking both label classes.

Use paired study-level bootstrap resampling for 95% intervals on differences,
with a fixed seed and recorded resample count. Retain valid replicate counts
when resamples lack a target class. Keep the 12 targets of each sampled study
together. These intervals describe this held-out checkpoint comparison, not
training-seed variability. Save per-study predictions, metrics, intervention
definitions, config/source/checkpoint and input identities in a fresh analysis
directory. Checkpoint disagreement must be investigated before interpreting
small ablation effects.

Interpret these as reliance measurements for the trained model. Embeddings
overlap and interact, so effects need not add up and cannot be assigned unique
percentages. Removing an embedding never omitted during training can create
unfamiliar inputs. The 3D unknown intervention has explicit training support.
Attention weights and embedding magnitudes alone are not contribution scores;
separately trained models would be needed to establish learning benefits, and
such training is not part of this plan. See the
[feature-ablation reference](https://captum.ai/api/feature_ablation.html) and
[removal-based explanation review](https://arxiv.org/abs/2011.14878), consulted
on 2026-09-13, for the method and interpretation limits.

## Completion and later evaluation

Implementation is ready for handoff when the source and configuration express
the single agreed architecture, old regional imports/callers are removed,
identities cover the new geometry and embeddings, the manual diagnostic is
available, and the diagram/catalog/documentation agree with the code.

Run relevant static formatting/lint checks, documentation/link review,
`rtk git diff --check`, and the catalog consistency check if scripts change.
**Do not write or run tests, launch training, perform optimizer-step checks,
schedule GPU jobs or submit a model.** Report which runtime behavior remains
unverified until the user's run; successful static checks do not establish
training correctness, accuracy or cost.

After the user launches the fresh fold-0 run, compare its saved results with
`crop140mm` and the recorded regional model. Preserve seed 42, `all_5fold_v3`,
the 904-study validation membership, labels, 2× validation image density,
pretrained backbone initialization and training budget. Record all execution
differences, including the historical determinism mismatch. The experiment's
factor is the complete spatial-token representation; no automatic baseline
rerun or extra seed is required.

Record macro/per-target AUC, BCE, training duration and peak VRAM from the
user's run. Measure inference cost separately on a matched workload before
considering deployment; the nominal token count alone does not establish
whether the model is affordable. Use a fresh artifact directory, retain
source/config/checkpoint identities and acknowledge unresolved small effects.
Any further training, backbone change or submission is a separate user action.
Move durable implementation and measured findings into the topic docs as work
finishes, and remove completed tasks from [ongoing work](docs/ongoing.md).
