# Active spatial token model

The active model applies target-specific attention MIL to three token sets from every study:
coarse tokens from a light scout on every canvas, one context glimpse per canvas and a budget of
detail glimpses placed by a demand head, all read by ReXNet-200, as described in
[learned zoom](#learned-zoom). The scout gives 361 coarse tokens per canvas, a 160-pixel context
glimpse 25 tokens and a 224-pixel detail glimpse 49 tokens, so a validation study with 51 canvases
and 17 detail glimpses yields about 18,400 coarse, 1,275 context and 833 detail tokens before
masking. The MIL head uses no global pooling, regional queries, token interaction or grid
reduction. The scorer stays 256→128→12 with its configured dropout, followed by per-target
weighted features and linear heads, shared by all token sets.

Tokens receive four additive embeddings, and glimpse tokens a fifth:

| Embedding | Definition |
|---|---|
| 1D | Sinusoidal middle-slice distance in mm from the acquisition midpoint |
| 2D | Scout cell anchor in the augmented canvas, normalized independently to each canvas axis; 2→64→256 GELU MLP. Glimpse tokens reuse the embedding of the scout cell nearest their own anchor |
| Plane | Learned Axial, Coronal, Sagittal embeddings |
| Contrast | Learned metadata pairs `(0,0)` and `(1,1)` for fluid sensitivity/fat suppression |
| Scale | Learned `context` and `detail` vectors (`glimpse_scale`, normal init 0.02); coarse tokens have none |

`encode_batch` adds them to the projected features and applies the shared `mil_norm`;
`pool_encoded` scores and pools all tokens (step 7 of [learned zoom](#learned-zoom)). Plane and
contrast lookup buffers derive from configured metadata rather than slot order. The ReXNet
adapter derives stride 32 and origin 0 from its convolutions, and the scout adapter origin 0 at
strides 16 and 32 in module order; other backbone mappings fail explicitly. Geometry and the
coordinate MLP execute in float32 outside autocast; embeddings are cast to visual-feature dtype.

Tokens carry no patient-coordinate geometry: the model reads neither LPS points nor the study
center, and visual validity alone decides token membership. The per-token points and their
geometry validity were removed with the [attention prior](#retired-attention-prior) on
2026-09-16. Series dropout remains 0.20, restoring one present type when necessary.

## Learned zoom

Implemented on 2026-09-16 as [candidate run 0](../ongoing.md#candidate-next-runs) and not yet
trained. It replaced [per-label crop selection](#crop-selection) and tests whether learned zoom adds
information on top of full slice coverage. `configs/baseline.yaml` carries it:

| Setting | Value | Meaning |
|---|---|---|
| `data.image_size`, `data.spacing_mm` | 360, 150/360 (0.4167 mm) | Prepared canvas, 150 mm |
| `data.scout_size` | 300 | Scout input, 0.5 mm; 19×19 stride-16 cells (8 mm) |
| `data.context_size`, `data.context_spacing_mm` | 160, 0.875 | Centred 336-pixel (140 mm) window read at 160 pixels |
| `data.crop_size` | 224 | Detail window at canvas resolution, 93 mm |
| `data.detail_canvas_fraction` | 0.333 | Detail budget per study |

The selection constants `LATENT_COVERAGE` (0.5), `STUDY_CLUSTERS` (16) and `KMEANS_ITERATIONS`
(5) live in `crop_selection.py`. `encode_batch` runs, in order:

1. Series dropout, study reflection on uint8 canvases, then affine, gamma/contrast and noise
   augmentation on the 360-pixel canvases, per series. Affine translation is a fraction of the
   canvas, so its millimetre range is unchanged; noise is drawn per 360-pixel pixel, and the
   downsamples below average it.
2. **Scout:** an antialiased bilinear downsample (`align_corners=False`) to 300 pixels, then the
   scout's stride-16 map (48 channels, 19×19) concatenated with its stride-32 map (576 channels)
   sampled at the stride-16 anchors, projected 624→256. Scout anchors map to canvas pixels with the
   half-pixel rule `x_canvas = 1.2 · (x_scout + 0.5) − 0.5` (origin 0.1, stride 19.2 pixels), and
   coarse geometry (2D xy, visual validity) uses those anchors with the canvas augmentation and
   reflection inverses. Every study must have visually valid coarse tokens.
3. **Demand head:** `d[j,t] = softplus(MLP(coarse token j))`, 256→256 GELU→12 in float32, last
   layer zero weights and bias `log(e − 1)`, so demand starts at 1 everywhere. It reads the same
   coarse tokens the attention reads; its first layer receives gradient only after the last layer
   leaves zero.
4. **Candidates and budget:** every (canvas, visually valid scout cell) whose 224-pixel window, top
   left `floor(anchor − 112 + 0.5)`, overflows the canvas by less than one canvas scout stride (19.2
   pixels) on both axes: rows and columns 5–13, 81 cells per canvas, with window centres from
   −35.0 to +29.2 mm around the canvas centre (the scout grid is not centred). A window's footprint
   is the 11×11 scout cells whose anchors lie inside it. Each study gets
   `min(ceil(0.333 × canvases), candidates)` detail glimpses: on fold 0, 7.0 per training study
   after series dropout (20.3 canvases) and 17.4 per validation study at 2× images (50.7 canvases).
5. **Selection (float32, no gradient):** greedy label-weighted facility location.
   - Per-study spherical k-means (16 clusters; farthest-point initialisation starting from the
     token closest to the study mean; 5 iterations) on detached, L2-normalised scout features
     taken before any embedding, over visually valid cells.
   - Coverage of coarse token `j` by candidate `g` is 1 when `j` lies in `g`'s footprint on the
     same canvas, otherwise `0.5 · max(0, cos(desc_g, centroid(cluster_j)))`, with `desc_g` the
     normalised mean feature over `g`'s valid footprint cells.
   - `F(S) = Σ_t Σ_j d[j,t] · max_{g∈S} cov(g, j)` with detached demand and invalid tokens
     weighted 0. Coverage does not depend on the label, so the label sum becomes one weight per
     token.
   - Each round adds the candidate with the largest marginal gain. Tokens inside a chosen window
     are covered; every other token's coverage is its cluster's best latent level `M_k`, so the gain
     is `Σ_k W_k · max(0, L_gk − M_k) + Σ_k U_gk · (1 − max(L_gk, M_k))`, with `W_k` the uncovered
     weight of cluster `k` in the study and `U_gk` its uncovered weight inside `g`'s footprint.
     Footprint sums are separable 9×19 box filters (`einsum`), recomputed each round only for the
     chosen canvas; studies run in parallel in a padded (study, canvas slot, candidate) layout.
   - Training samples each round by Gumbel-max on `log gain`; evaluation takes the argmax. A
     candidate is never taken twice, and zero-gain candidates are taken only when nothing with
     gain remains, so a study has no detail glimpse only without selectable candidates.
6. **Glimpses:** the context glimpse is the centred 336-pixel window, antialiased to 160 pixels
   (0.875 mm); detail glimpses are integer 224-pixel windows of the canvas, zero outside. Both are
   normalised and read by ReXNet-200's plain `forward_features` in two calls (5×5 and 7×7 tokens)
   with a shared 2560→256 projection. Token anchors map to canvas pixels (context origin 12.55,
   stride 67.2; detail top left plus 32-pixel steps) and give each token its own visual validity and
   its nearest scout cell (`round((anchor − 0.1) / 19.2)`, clamped), whose 2D embedding it takes;
   1D, plane and contrast come from the canvas. The canvas tensor is released before ReXNet-200
   runs. A batch without detail glimpses skips the detail call.
7. **Pooling:** one float32 softmax per study and label over all visually valid coarse, context
   and detail tokens. Logits are the attention MLP's score; detail tokens add `log d̄[g,t]`, the
   log of the mean demand, with gradient, over the valid coarse tokens in their glimpse's
   footprint, so demand competes with unchosen regions and learns only through this term. The
   shared head classifies the pool, and the soft-target BCE is the only loss. The coarse tokens
   pooled alone with the same attention give the draft, logged as `val_draft_macro_auc`.
   Validation also logs `val_attention_share_coarse`, `_context` and `_detail` (each label's mean
   attention share over studies, averaged over labels); the per-epoch metrics JSON stores the
   per-label shares under `attention_share`.

`encoded["detail_glimpses"]` keeps each detail glimpse's study, canvas, cell and top-left offset
for analysis. The demand head and scale embeddings train at the head learning rate; weight decay
follows the existing rule (embedding tables decay, like plane and contrast). FP16 inference
(`use_fixed_backbone_chunks`) pads glimpses to fixed 64-image chunks and warms both input sizes.
Construction probes ReXNet-200 at both glimpse sizes and the scout at 300 pixels, and requires
crops smaller than canvases, an integer context window centred on the canvas and a square,
isotropic scout grid; CoAtNet's fixed 224-pixel input fails at the context size.

**Cost.** The per-component parameter and compute budget is in
[swapping a backbone](backbone-swaps.md#current-budget). ReXNet-200 reads about 874k pixels per training study (−27% against shared crops'
24 × 224²) and 2.17 million per validation study (+80%). A GPU profile on the RTX 3090 (BF16,
random initialisation, the eight heaviest training studies with series dropout off, 32 canvases
and 11 detail glimpses each; `outputs/profiling/learned-zoom-gpu-sweep`):

| Studies | Canvases | Detail glimpses | Step | Selection | Peak allocated |
|---:|---:|---:|---:|---:|---:|
| 6 | 192 | 66 | 0.426 s | 13.8 ms (3.2%) | 17.9 GiB |
| 7 | 224 | 77 | 0.486 s | 14.7 ms (3.0%) | 20.9 GiB |
| 8 | 256 | 88 | CUDA out of memory | | about 23.8 GiB by extrapolation |

Peak memory grows by about 0.092 GiB per canvas with its detail share. Series dropout keeps real
batches far below 256 canvases: simulating 200,000 fold-0 training batches of eight gave 163
canvases on average (about 15 GiB), 196 at the 99th percentile (18.3 GiB) and at most 226
(21 GiB); 256 needs all 48 series of eight maximum-load studies kept. The label-private step on
the same 256 canvases with 192 crops took 0.46 s and 21.3 GiB (`outputs/profiling/private-crops-gpu`).
CPU preparation of the same eight studies at 360 pixels took 22% longer than at 300 pixels with
warm caches (7.8 against 9.5 studies per second, `outputs/profiling/learned-zoom-preprocessing-360`
and `-300-reference`), and loader batches hold 1.44× the pixels. Launch the fold-0 run with:

```bash
rtk proxy uv run --locked just train learned-zoom configs/baseline.yaml 0
```

After training, `scripts/adhoc/probe_glimpses.py` scores the selected checkpoint with detail
glimpses as trained, removed, random, and at half and double the budget.

## Crop selection

Retired on 2026-09-16 by [learned zoom](#learned-zoom). Implemented on 2026-09-15 from the
[crop selection plan](../../crop-selection-plan.md); its runs are tracked in
[ongoing work](../ongoing.md#crop-selection). The last recipe, shared crops, scored 0.879626
([result](../validation/2026-09-16-shared-crops-result.md)): 300-pixel canvases at 0.5 mm read
whole by the scout; the per-label coarse attention, pooled once with gradient, as the value map;
each label independently choosing `data.crops_per_label` (2) 224-pixel crops (112 mm) by
footprint value with Gumbel noise in training, spreading over unused planes and canvases first;
ReXNet-200 on all 24 crops per study without deduplication; fine token scores coupled to the
coarse score of their cell; and a per-label sigmoid gate mixing the coarse pool with a softmax over
all of the study's fine tokens. Earlier revisions (160-pixel crops, a summed value map, crops on
75% of canvases, label-private pooling with label FiLM) are in the linked results. The full
section and shape diagram before the rewrite, and the archived code, are in the
[historical crop-selection sources](../history/crop-selection-sources/README.md).

## Retired token graph

A local kNN message-passing graph over all spatial tokens was implemented on 2026-09-14
and retired on 2026-09-15 because trained models did not use it. It had replaced the
additive 3D embedding, `unknown_3d` and its study-level 3D dropout, which stay removed.
Two fold-0 runs, both measured with the encoding diagnostic:

| Run | Graph setup | Macro AUC | Control | Without graph |
|---|---|---:|---|---:|
| `token-graph` | Two zero-initialized residual layers before `mil_norm`, head learning rate | 0.892376 | Champion 0.892360 | +0.000007 |
| `graph-forced` | Default output initialization, update after `mil_norm`, learning rate 0.0018 without weight decay | 0.892679 | `00-baseline` 0.892763 | +0.000039 |

The [token-graph result](../validation/2026-09-14-token-graph-result.md) owns the
measurements. The plan and graph-era sources are archived as
[historical token-graph sources](../history/token-graph-sources/README.md); the run
source archives `outputs/token-graph/source_snapshot.zip` and
`outputs/graph-forced/source_snapshot.zip` reproduce each run. Removing the graph
changed the source, spatial-token and preprocessing identities, so every earlier
checkpoint, including `00-baseline` and `attention-prior`, requires its archived sources.

## Retired attention prior

Implemented on 2026-09-15 from the
[position research](../research/position-encoding.md#phase-1-head-only-changes) and retired on
2026-09-16. Its fold-0 run [regressed by 0.002177](../validation/2026-09-15-attention-prior-result.md)
against the matched `00-baseline` control, and its learned priors stayed nearly flat. With
`model.attention_prior: gaussian_1d_2d_3d` it added three per-target log-biases
`-0.5 * sum_k ((q_k - mu_k) / sigma_k)^2` (float32, `mu = 0` and `sigma = 2` initially, head
learning rate without weight decay) to the coarse and fine attention scores before masking:

| Term | Tokens | Input `q` | Parameters |
|---|---|---|---|
| 3D | Geometry- and visually valid; others got zero | `(abs(dx), dy, dz)` in 100 mm units, relative to the study's mean valid token point | Per target, `[12, 3]` |
| 1D | Visually valid | `abs(1D position)` in 100 mm units | Per plane and target, `[3, 12]` |
| 2D | Visually valid | 2D embedding input: `abs(x)` for Axial and Coronal, signed `x` for Sagittal, always signed `y` | Per plane and target, `[3, 12, 2]` |

The 3D term was the only reader of each token's patient point, the middle-slice LPS anchor with
reflection `S = diag(−1, 1, 1)` applied to the absolute point, and of its geometry validity.
Retirement removed `attention_prior.py`, `model.attention_prior`, `configs/attention-prior.yaml`,
those per-token points and validity, the collated `patient_maps` and `geometry_valid` tensors
and the diagnostic's prior variants; the [reflection preview](../data-preparation/reflection-geometry-and-previews.md)
computes its own LPS anchors. The measured run's sources are in
`outputs/attention-prior/source_snapshot.zip`, and the last implementation is in
`outputs/label-private-crops/source_snapshot.zip`.

## Five-embedding predecessor

The `spatial-tokens-five-embeddings` run, and every later run up to the champion, also
added a 3D embedding (patient LPS minus the accepted study center, divided by 100 mm,
through a 3→64→256 GELU MLP), used a learned `unknown_3d` vector for missing geometry and
replaced available 3D with it for 0.10 of studies during training. It kept seed 42,
`all_5fold_v3`, 224 pixels, 140 mm, 2× validation density, pretrained initialization,
augmentation, labels, loss, optimizer and ten-epoch budget. Strict determinism remained
disabled as in the incoming recipe; the historical average-pooling reference enabled it,
so this execution difference must accompany later comparisons. The five embeddings and
removal of the regional branch constituted one experiment. It was launched with:

```bash
rtk proxy uv run --locked just train spatial-tokens-five-embeddings
```

The completed run is saved in `outputs/spatial-tokens-five-embeddings/`. It selected
epoch 10 at 0.889506 fold-0 macro AUC and **0.929 public AUC**, later surpassed by
[3dsampling at 0.930](../validation/2026-09-13-3dsampling-validation-comparison.md); see the
[validation comparison](../validation/2026-09-13-spatial-token-validation-comparison.md)
for target changes, uncertainty, learning curves, timing and memory, and the
[submission record](../inference/2026-09-13-spatial-token-submission.md).
Historical checkpoints require their original
source bundles; current source/config identities reject them without migration.
